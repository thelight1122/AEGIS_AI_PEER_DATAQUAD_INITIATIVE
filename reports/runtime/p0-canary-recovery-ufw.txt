  - tcpdump captured the SYN because AF_PACKET ingress precedes netfilter

LAYER 8 - WARP PERSISTENCE TEST (Auditor sequence step 2)
===============================================================
QUESTION: can the cloudflare-warp table return without blocking inbound SSH,
once a split-tunnel bypass covering the VM addresses is configured?

ANSWER: NO.

Observed with the bypass configured and warp-svc restarted:

  warp-svc                      active
  table inet cloudflare-warp    present
  input chain                   type filter hook input priority filter; policy drop
  rules matching "dport 22"     0

External reachability during that window, from an egress the NSG permitted:

  20.122.189.26:22    unreachable
  20.122.189.26:4001  unreachable   (NSG opens 4001 to *, no JIT involved)
  20.122.189.26:8080  unreachable

The bypass governs OUTBOUND routing. It generates no inbound accept rules, so
the kill switch blocks every inbound port, not only 22. Ports 4001 and 8080 are
the clean discriminator: they are open to any source at NSG priorities 1005 and
1006 and were unreachable regardless.

A workaround in a separate nftables table is not available. At a given hook all
base chains are traversed and a `drop` verdict in any chain is final, so an
`accept` in another table cannot override WARP's policy drop. The accept must
live inside WARP's own table, where the daemon reverts it, or the daemon must
not be running.
